# Authentication (Admin)

**Files:** `app/Http/Controllers/Auth/AuthController.php`, `app/Http/Controllers/Admin/SecurityController.php`, `app/Services/TwoFactorService.php`, `app/Support/Totp.php`, `app/Models/LoginEvent.php`, `resources/views/auth/{login,two-factor}.blade.php`, `resources/views/admin/security/index.blade.php`

- Session-based login with the default `web` guard, using `username` + `password` (optional "remember").
- The password is checked first; users whose `role` is not `admin` are refused with "Unauthorized access." and never signed in. Subscribers can't use the panel; they only use `/m3u` and `/play`.
- **Login limits:** after `AuthController::MAX_ATTEMPTS` (5) wrong passwords for one username from one IP, sign-in is refused for a minute ("Too many sign-in attempts. Try again in N seconds."), and after `MAX_ATTEMPTS_PER_IP` (20) failures from one IP with any usernames. A subscriber trying the panel login with the right password counts as a failure. A successful sign-in clears the per-username count. An unknown username still costs a password check, so response time doesn't tell who exists.
- **Two-factor sign-in (optional, per admin):** with it on, a right password sends the admin to `/two-factor` (the pending sign-in lives in the session for `TWO_FACTOR_MINUTES` = 5) and only a right code signs them in. Accepted: the 6-digit code from an authenticator app (TOTP, RFC 6238, SHA-1, 30 s, one step of clock drift; a code works once, `users.two_factor_last_step`) or a recovery code (works once). Wrong codes are limited like passwords (5 per admin + IP, then a minute's wait) and recorded.
- **Setting it up** (**Security** in the sidebar, `/admin/security`): *Set up* shows a QR code and the key (`Totp::uri`, SVG made by `bacon/bacon-qr-code`), and it turns on after the first right code, which also creates 8 recovery codes (`xxxxx-xxxxx`, shown once). *Set up*, *Create new recovery codes* and *Turn off* ask for the password again (limited too), so a stolen session can't enrol someone else's phone. Turning it on or off also ends all "Keep me signed in" logins (`remember_token` is replaced). A code and a recovery code are claimed atomically (a changed `APP_KEY` makes an unfinished setup start over instead of failing), so two parallel requests can't both use it. The secret is stored encrypted, recovery codes only as HMAC hashes. Losing the phone and the codes: an administrator with server access runs `php artisan tinker` and clears `two_factor_secret`, `two_factor_confirmed_at`, `two_factor_recovery_codes` on the user.
- **Sign-in history:** every attempt is recorded in `login_events` (success, wrong password, subscriber trying the panel, wrong code, two-factor turned on/off) with IP and browser. The last 30 are on the Security page; rows older than `LoginEvent::KEEP_DAYS` (180) are removed by `model:prune`.
- On success the session is regenerated and the user goes to `intended()` or `admin.dashboard`.
- `GET /login` sends an already-logged-in admin straight to the dashboard.
- Logout invalidates the session and regenerates the CSRF token.
- The sign-in page has the language menu and the theme switch under the card. The `locale` and `theme` cookies outlive the session, so the chosen language and theme stay after sign-out ([localization.md](localization.md)). Login error messages are translated.

The admin route group uses `auth` and `admin` (`App\Http\Middleware\EnsureAdmin`). A signed-in user who isn't an admin is signed out and sent to the login page.

**First admin** (`AdminSeeder`, run by `db:seed` and on Docker start): created only if a user with `ADMIN_USERNAME` (default `admin`) doesn't exist, and never changed afterwards. The password is `ADMIN_PASSWORD` from `.env`. Without it, local installs get `admin123`, and any other environment gets a random 16-character password, printed once by `db:seed`.
